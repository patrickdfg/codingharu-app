# 학습 관찰 · 프로젝트 추천

선생님 메뉴 `admin.html#learning`에서 학생과 월을 고른다. 학생 화면에는 결과 분석을 공개하지 않고 선택형 짧은 설문만 제공한다.

- 주 1회 2시간 수업, 그중 사이트 활동 약 1시간을 전제로 한다. 사이트 이용 시간으로 수업 전체의 학습량을 평가하지 않는다.
- 시간은 로그인한 학생의 최상위 수업 화면에서만 추정한다. 비활성 창·백그라운드·마지막 조작 후 60초를 넘는 시간은 제외한다. 생각·종이·실물 로봇 활동은 누락될 수 있다. 문제별 실제 풀이 시간이 아니다.
- 약 45초마다 누적 스냅샷을 저장한다. 전송 실패는 학생별 기기 대기열에 남겨 다음 접속 때 다시 보낸다. 같은 세션 재전송은 시간을 중복 합산하지 않는다. 기기의 사이트 데이터를 삭제하면 미전송 기록도 사라진다.
- 워크북 진행은 저장 시점의 완료/전체 표시이며 정답률이 아니다. 도입 전 시간·오답·힌트 횟수는 소급 계산하지 않는다.
- 설문은 2분 이상 활동한 뒤 저장/완료 이벤트에서 주 1회 이하로 자동 제안한다. 자동 제안을 건너뛰면 그 기기에서 7일간 다시 띄우지 않는다. `오늘의 관심` 버튼으로 자발적으로 답할 수 있다. 재미·난이도·막혔을 때 접근 방식·관심 분야 1~3개를 묻는다. 카메라·녹음·키 입력 내용은 수집하지 않는다.
- 월별 화면에 최대 8개 최근 설문을 표시하고, 추천은 최근 설문 기준 90일 내 최대 4개를 가중 집계한다. 현재 시점에 90일 넘게 설문이 없으면 새로 물어보도록 안내한다. 관심·자기보고 난이도 기반의 상담 초안이며 실력/적성 판정이 아니다.
- 기존 프로젝트 연구소 215개 중 관심 분야와 난이도가 가까운 주제를 최대 3개 연결한다. 선수 개념은 분야별 확인 항목이며 해당 학생의 학습 완료를 판정하지 않는다. 교사가 학습 상황을 확인하고 최종 선택한다.
- 로봇 활동 분과 교실 관찰 메모는 선생님이 따로 입력한다. 자동 활동 시간과 합산하지 않는다. 새 기록은 `학습 관찰` 시트에 자동 생성되고 학생 삭제 시 함께 제거된다.

## 배포

공개 앱 파일은 Pages로 배포된다. `server/record.gs`는 기존 Apps Script 편집기에서 코드를 교체하고 **기존 배포 → 수정 → 새 버전**으로 반영해야 한다. 별도 `setup` 실행은 필요 없다. 서버 반영 전에는 수업/기존 기록은 유지되고 새 수집은 시작하지 않는다. 교사 화면에는 서버 갱신 안내가 표시된다.

## 채점 교안 연결

일반 저장/완료 클릭으로 정답을 추측하지 않는다. 기존 교안에는 아직 아래 이벤트를 연결하지 않았으므로 정답률·힌트 항목은 `미수집`으로 나온다. 교안별 실제 채점 지점에서 다음 이벤트를 보내야 집계된다. 이 값은 학생 브라우저의 교육용 관찰이며 시험/자격 인증 증거로 사용하지 않는다.

```js
document.dispatchEvent(new CustomEvent('codingharu:attempt', { detail: { correct: true } }));
document.dispatchEvent(new CustomEvent('codingharu:hint'));
```

문항별 최초 시도~완료 시간·오답 원인을 보려면 문항 ID와 시작/종료·채점 결과를 해당 교안에 추가 연결해야 한다. 현재 세션 기반 추정치와 구분한다.

검증: `node test/learning.test.cjs`, `node test/member-delete.test.cjs`, `node test/admin.test.cjs`; 브라우저에서 활성/유휴/비활성 시간, 설문 건너뛰기/저장, 교사 화면 추천·로봇 관찰·학생 전환을 확인한다.
